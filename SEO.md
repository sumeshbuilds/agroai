# Ranking AgroAI on Google

Everything search engines need is generated by the app. This file covers what
ships, what to set on the host, and the steps that happen outside the codebase.

## What ships in code

| Piece | File | Output |
| --- | --- | --- |
| Canonical origin and copy | `src/lib/site.ts` | Shared URL, title, description, keywords |
| Sitemap | `src/app/sitemap.ts` | `/sitemap.xml` with `/` and `/odisha` |
| Crawl rules | `src/app/robots.ts` | `/robots.txt` (allows public pages, blocks `/api/`) |
| Share card | `src/app/opengraph-image.tsx` | 1200×630 PNG at `/opengraph-image` |
| Homepage metadata + JSON-LD | `src/app/page.tsx` | Title, description, canonical, Organization, WebSite, SoftwareApplication |
| Odisha landing page | `src/app/odisha/page.tsx` | Keyword-targeted page, FAQ, breadcrumb, FAQPage schema |
| Private screens | `src/app/(dashboard)/layout.tsx`, `login`, `onboarding`, `camera` | `noindex, nofollow` |
| PWA manifest | `src/app/manifest.ts` | Name, scope, language, category |

The canonical host is **`https://www.agroai.co.in`**. The apex domain issues a
308 redirect to `www`, so every canonical tag, sitemap entry and JSON-LD `@id`
points at `www` to avoid "Page with redirect" reports.

## 1. Environment (Vercel → Project → Settings → Environment Variables)

| Variable | Value | Where |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | `https://www.agroai.co.in` | Production (and Preview if you want correct preview canonicals) |
| `GOOGLE_SITE_VERIFICATION` | Token from Search Console | Production |

`GOOGLE_SITE_VERIFICATION` is only the `content` value, not the whole meta tag.
After changing either variable, redeploy — metadata is built at deploy time.

## 2. Google Search Console

1. Open <https://search.google.com/search-console> and add a **Domain** property
   for `agroai.co.in`. Domain properties cover the apex and `www` in one place.
   Verify with the DNS TXT record your registrar provides.
   - If DNS is inconvenient, add a **URL-prefix** property for
     `https://www.agroai.co.in`, set `GOOGLE_SITE_VERIFICATION`, redeploy, then
     click **Verify**.
2. **Sitemaps → Add sitemap** and submit:

   ```
   https://www.agroai.co.in/sitemap.xml
   ```

3. **URL Inspection** → enter `https://www.agroai.co.in/` → **Request indexing**.
   Repeat for `https://www.agroai.co.in/odisha`.
4. Come back after 48–72 hours and open **Indexing → Pages**. A brand-new site
   often sits at "Discovered – currently not indexed" for a few days. That is
   normal; do not resubmit repeatedly.

## 3. Bing and the rest

- <https://www.bing.com/webmasters> can import the site directly from Search
  Console. Submit the same sitemap.
- Optional: add IndexNow later if you start publishing frequent content.

## 4. Signals for "agricultural startup in Odisha"

Files make the site *eligible*; these steps make it *credible*.

- **Google Business Profile** — create one only if the venture can be verified at
  a Kalahandi service area. Use the same name, logo and description as the site.
- **Consistent profiles** — LinkedIn, GitHub, Startup Odisha / incubator pages,
  and any DPIIT or FPO listings that genuinely apply. Only claim what is true.
- **Earned links** — local journalism, Krishi Vigyan Kendra, OUAT extension
  networks, FPOs, agri-incubators and panchayat programmes. One relevant link
  from an Odisha agriculture site is worth more than fifty directory listings.
- **Real proof** — photos and notes from the Kalahandi pilot (with farmer
  permission), field results and a changelog. Thin districts pages, spun copy or
  invented numbers will hurt more than help.

## 5. Targeting the keywords

- `agroai odisha` and `agroai kalinga` are **brand queries**. Once the site is
  indexed, the homepage title, the `/odisha` page and the Organization schema
  (`alternateName: ["AgroAI Odisha", "AgroAI Kalinga"]`) are what Google reads.
- `agricultural startup in odisha` is a competitive category query. It needs the
  `/odisha` page to stay substantial and to be linked from credible Odisha
  sources. Keep one strong page rather than many near-duplicate district pages.
- Keep the visible `<h1>` honest and specific. Do not stuff the keywords into
  headings that read badly for a farmer.

## 6. Verify a deployment

```bash
curl -s https://www.agroai.co.in/robots.txt
curl -s https://www.agroai.co.in/sitemap.xml
curl -sI https://www.agroai.co.in/opengraph-image
curl -s https://www.agroai.co.in/odisha | grep -E 'canonical|og:image|ld\+json'
```

Then:

- **Rich Results Test** — <https://search.google.com/test/rich-results> for
  `https://www.agroai.co.in/odisha`. Expect FAQ, Breadcrumb and Organization.
- **PageSpeed Insights** — <https://pagespeed.web.dev> for `/` and `/odisha`.
- **Schema validator** — <https://validator.schema.org>.

## 7. Honest expectations

- Indexing is not instant. A new domain can take days to weeks for the first
  crawl, and longer for ranking.
- No file guarantees a ranking. Sitemap + canonical + structured data remove
  obstacles; links and real content create rank.
- Search Console is the source of truth. If a page is "Crawled – currently not
  indexed", improve the content and internal links before requesting again.
